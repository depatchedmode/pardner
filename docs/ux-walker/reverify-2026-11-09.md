## New regressions and observations

There are no hard regressions: no broken flow, no console errors on the walked pages and no page overflow. Some fixes moved a cosmetic cost elsewhere, and I noticed a few other things:

1. **The invite history's expiry column now wraps.** Keeping "Waiting to be used" on one line pushes "Expires in 24 h · Nov 10, 12:56 PM" onto two lines in every issued row of the 520 px dialog (`inv-chromium-2-created.png`). It is consistent, but the row is now two lines tall. Low.
2. **A long unbroken name makes a 6-line Continue button.** The page no longer overflows (F-014-04), but the button grows to about 130 px tall (`id-3-long-name-error.png`). Truncating with an ellipsis would read better. Low.
3. **The outage sentence appears twice.** With the service stopped, the page banner and the inline error both say "The local Pardner client did not respond. Check that it is still running, then retry.", and each has its own retry button (`out-1-panel-status.png`). Related to F-085-01. Low.
4. **Clicking the shown invite text in Chromium toggles the selection.** The first click selects it all, and a second click clears it (`0-0`). In WebKit it is the reverse (see F-038-01). It is not clear whether this changed with the `onClick` select; noted for the follow-up on F-038-01. Low.
5. **A used link pasted into an already-open signed-out tab shows no notice.** When only the hash changes, the used-link notice did not appear. A fresh tab shows it correctly (`logs/signed-out.log`, first run). Not confirmed as a regression; the original walk did not test this path. Low.
6. **The identity helper text keeps the Git claim after the person types.** On tab B the helper still says "Name filled in from your Git configuration; enter your email." although the person typed both fields themselves (`id-4-tabB-identity-exists.png`). Suggestion.
7. **This predates the fixes: `client list` against a stopped client with a stale connection file gives `INTERNAL_ERROR: fetch failed`, not `CLIENT_NOT_RUNNING`.** It was already noted in STORY-009 (#25). It adds a fifth "not running" wording to F-012-03.
