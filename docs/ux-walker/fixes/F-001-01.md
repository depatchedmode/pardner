# F-001-01: CLI noise and unclear `open` / `client operation` results

Quick-fix unit qf-1. Findings: F-001-01, F-046-03, F-003-01, F-003-02, F-012-02, F-128-01.

## What was wrong

- Every `pardner` command printed Node's `ExperimentalWarning: SQLite is an experimental feature` and a `--trace-warnings` hint on stderr. The detached `client serve` child runs the same bin, so the same lines were appended to `client.log` on every service start (F-001-01, and the warning part of F-046-03).
- When the OS browser launcher started but failed, the CLI said `Browser launch failed; retry client open`. Retrying fails the same way, and the person typed `pardner open`, not `client open` (F-003-01).
- `pardner open --output-file FILE` did not name the file it wrote or say that the link lasts 60 seconds (F-003-02, F-012-02).
- `client operation` with malformed `--request` JSON returned `INTERNAL_ERROR` with the raw SyntaxError. With `--request` left out it sent `{}` and got back a misleading `FORBIDDEN` (F-128-01).

## What changed

- `bin/pardner.js` drops only the SQLite `ExperimentalWarning` and passes every other warning on. It then loads the CLI with a dynamic import, because a static import would be hoisted above the filter.
- `lib/client-cli.js`:
  - A failed launch now says `Browser launch failed; run pardner open --output-file FILE and open that address in your browser within 60 seconds`.
  - `open --output-file` adds `outputFile` (the absolute path) and `expiresInSeconds: 60` to its result. `localUrl` and `launchIssued` stay as they were, because `test/control_runtime_test.py` asserts `launchIssued`.
  - `client operation` checks `--request` before it asks for an agent grant. A missing request gets `INVALID_ARGUMENT: Supply --request with the operation JSON`, and bad JSON gets `INVALID_ARGUMENT: --request must be valid JSON`. The second message matches the standalone `pardner operation`.

## Not addressed

- F-046-03, epoch timestamps: `expiresAt` is still a raw epoch in milliseconds. Changing it would alter an output field that other callers read.
- F-046-03, errors printed twice: a failure still prints the JSON line on stdout and `CODE: message` on stderr. That is the CLI's documented contract.

## Verification

- `test/client-cli.test.js`:
  - Every `pardner` call made through the shared helper asserts that stderr has no `ExperimentalWarning`. So does `client open`. This check failed against the previous `bin/pardner.js`.
  - The detached service's `client.log` has no `ExperimentalWarning`.
  - `open --output-file` returns `outputFile` and `expiresInSeconds: 60`.
  - `client operation` with malformed JSON, and with `--request` left out, returns the two `INVALID_ARGUMENT` refusals.
- `npm run test:cli`: 22/22 pass under Node 24.11.1.
- `python3 -B -m unittest discover -s test -p control_runtime_test.py`: see the qf-10 report (F-134-01); it covers the `launchIssued` assertion.
