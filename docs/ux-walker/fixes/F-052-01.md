# F-052-01: Wrapping labels, invisible script focus and Courier code

Quick-fix unit qf-5. Findings: F-052-01, F-034-04, F-036-03, F-104-02, F-106-01, F-097-06, F-004-04, F-014-04.

## What was wrong

- The "+N" overflow marker on cards and in the header could wrap, stacking "+" above the digit (F-052-01).
- "Waiting to be used" wrapped onto two lines in the invitation history, at a different point on each row (F-034-04, F-036-03).
- Activity events and Goals articles take focus from script (`tabindex=-1`) but had no visible focus style, so jumping to a goal or loading older activity left no visible cue (F-104-02, F-106-01).
- The Goals empty state was centred under a left-aligned heading (F-097-06).
- Inline `code` used the browser default monospace, which is Courier in WebKit (F-004-04).
- A long unbroken name in "Continue as …" widened the identity form past the viewport (F-014-04).

## What changed (`ui-prototype/src/pardner.css`)

- `.avatar-more` gets `white-space: nowrap`.
- `.invite-list .invite-state` gets `white-space: nowrap`. The history grid's state column is now `max-content`, so the expiry column takes the remaining width. Without that, the unwrapped label ran into the expiry text.
- `.event:focus` and `.goal:focus` share the existing `.event:focus-visible` outline.
- `.goals > .empty` is left-aligned.
- Inline code (`:not(pre) > code`) uses `ui-monospace, SFMono-Regular, Menlo, monospace` at `0.92em`. Markdown code blocks (`pre > code`) are unchanged. Applying the font to every `code` changed glyph positions in code blocks and broke the scroll-shadow pixel check in `test/pardner-ui.test.js`.
- `.client-entry form button` gets `max-width: 100%; overflow-wrap: anywhere`.

## Not addressed

- F-004-04 also suggested `white-space: nowrap` on short commands. This wasn't needed: `pardner open` no longer wraps at 1440px.
- F-036-03 suggested shared column tracks across rows. Each row is still its own grid. With the state label on one line the columns line up, but a long expiry string can still wrap ("… 12:41 / PM") at the dialog's width.
- F-106-01, "Showing N of M" scrolls out of view after Show older activity: no boundary marker was added.

## Verification

These are visual-only CSS changes, so no test was added. Checked against a client built and served from this worktree (`node bin/pardner.js client serve --data …`):
- WebKit 1440×900: the signed-out screen shows `pardner open` in a sans monospace. A 90-character unbroken name wraps inside the Continue button (`scrollWidth` stays 1440).
- Chromium: the history state stays on one line at 1440×900 and at 390×844. The Goals empty state is left-aligned. A focused Activity event shows the accent outline (`outline-style: solid`).
- An in-process client with 8 Actors shows "+3" on one line at 32px height.
- `npm run test:ui`: 66/66 pass.
