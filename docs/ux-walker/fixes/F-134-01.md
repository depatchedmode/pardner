# F-134-01: Control runtime usage refusals look like an outage

Quick-fix unit qf-10. Findings: F-134-01, F-134-02, F-144-01, F-144-02.

## What was wrong

- Every `control cli` refusal was coded `CONTROL_RUNTIME_UNAVAILABLE`. That includes usage mistakes: a missing `--agent`, a lifecycle, client or bridge command, and a protected flag. An agent that keys off the code would read these as a service outage and retry (F-134-01, F-144-01).
- Running `control` against a directory with no `config.json` printed the raw Python `[Errno 2] No such file or directory` text (F-134-02).
- `control open --output-file FILE` without the `--` separator failed with argparse's bare "unrecognized arguments" message. Nothing said that `--` is required (F-144-02).

## What changed

All changes are in `scripts/control-runtime.py`.

- New `ControlUsageError`, a subclass of `ControlError`. The `cli()` guards and the `open` argument check raise it. The guards are: no coordination command or a lifecycle/client/bridge command, a protected flag, and a harness missing from `config.agents`.
- `main()` reports `ControlUsageError` in the `cli` JSON envelope as `INVALID_ARGUMENT`. Every other failure keeps `CONTROL_RUNTIME_UNAVAILABLE`.
- `Controller.__init__` turns a missing `config.json` into `<home> is not a Pardner control installation (no config.json); pass --home or set PARDNER_CONTROL_HOME`.
- `main()` now uses `parse_known_args`. When unknown options appear before `--`, the argparse error adds `arguments for cli/open go after --, e.g. control open -- --output-file FILE`. Exit status 2 is unchanged.

## Not addressed

- The client's refusal of an agent credential (an HTTP error from the service) keeps `CONTROL_RUNTIME_UNAVAILABLE`. It comes from the service, not from the command line.

## Verification

- `test/control_runtime_test.py`:
  - The JSON-envelope test now expects `INVALID_ARGUMENT` for a guard refusal.
  - New test: a missing `--agent` and a protected flag give `INVALID_ARGUMENT`, while a service that cannot be verified still gives `CONTROL_RUNTIME_UNAVAILABLE`.
  - New test: a directory without `config.json` gets the installation message and no `Errno` text.
  - New test: `control open --output-file FILE` without `--` explains the separator.
- `npm run test:control-runtime` (UI build, then `python3 -B -m unittest discover -s test -p control_runtime_test.py`): 23 tests, all OK. This includes the real-service test that asserts `launchIssued` on `open --output-file`.
