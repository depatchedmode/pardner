# F-132-01: Bridge configuration errors read as crashes or name internal fields

Quick-fix unit qf-9. Findings: F-132-01, F-132-02, F-133-01.

## What was wrong

- A malformed `bridge.json` produced `INTERNAL_ERROR` with the raw SyntaxError text. The message did not name the file (F-132-01).
- Running a client bridge without `--token-file` failed with `Bridge configuration requires replicaId`. That names an internal field of standalone mode, not the missing flag (F-132-02, F-133-01).
- The help line for `pardner bridge reconcile` left out `[--token-file FILE]`, although a client bridge's reconcile needs it (F-133-01).

## What changed

- `lib/agent-bridge.js` `bridgeConfig()`:
  - A configuration file that is missing or is not JSON now gets `INVALID_ARGUMENT: The bridge configuration <path> must be readable JSON (<reason>)`.
  - When no credential file is given and `replicaId` or `dataDirectory` is missing, the refusal now reads `Supply --token-file FILE for a client bridge, or set replicaId and dataDirectory for a standalone service bridge`.
- `lib/cli.js`: the `bridge reconcile` help line now ends with `[--token-file FILE]`.

## Not addressed

- The second half of F-132-02 is not part of this unit's change. A missing credential file still gets the same message as a malformed one: "must hold the JSON written by client agent-grant".
- `docs/PARDNER-BRIDGE.md` is not in this unit's file list, so its reconcile examples are unchanged.

## Verification

- `test/bridge-integration.test.js`:
  - A configuration with no credential gets the new `--token-file` refusal with code `INVALID_ARGUMENT`.
  - A malformed configuration and a missing one each get `INVALID_ARGUMENT` with a message that names the file.
- `test/pardner-brand.test.js`: the installed `pardner help` lists `[--token-file FILE]` on the `bridge reconcile` line.
- The bridge test files pass 88/88: `agent-bridge`, `bridge-integration`, `bridge-config-retirement`, `bridge-process`, `bridge-review-regressions`, `bridge-retirement` and `bridge-rehearsal-support`.
- `npm run test:cli` passes 22/22 under Node 24.11.1.
