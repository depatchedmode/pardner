# F-014-05: clearer identity, harness and revoke errors (quick fix qf-2)

Findings: F-014-05, F-123-01, F-043-03, F-045-03, F-130-04, F-014-03, F-019-01, F-022-02
Stories: STORY-014, STORY-019, STORY-022, STORY-043, STORY-045, STORY-123, STORY-130

## Changes

| Where | Before | After |
| --- | --- | --- |
| `profile()` name too long (`lib/client-identity.js`) | `INVALID_ARGUMENT` "Supply a name" | `INVALID_ARGUMENT` "Use a name of at most 200 characters" (an empty name still gets "Supply a name") |
| `setupAgent()` and `POST /projects/:id/agent-grant` with an unknown harness | "Unsupported execution harness" | "Unsupported execution harness; use openai-codex, anthropic-claude-code or cursor" (built from `HARNESS_IDS` as `UNSUPPORTED_HARNESS`) |
| Revoking a member when you are not the creator | `FORBIDDEN` "Only creator may revoke other memberships" | `FORBIDDEN` "Only the project creator can remove other members" |
| Creator revoking her own membership | `FORBIDDEN` "Only creator may revoke other memberships" | `FORBIDDEN` "The project creator's own membership can't be revoked" |
| Revoking an agent ID that is not an agent in the project | `FORBIDDEN` "Agent belongs to another human" | `NOT_FOUND` (404) "No agent with that ID in this project" |
| Revoking another person's agent | `FORBIDDEN` "Agent belongs to another human" | unchanged |
| `POST /identity` with values that differ from the saved identity | `IDENTITY_EXISTS` "Identity already initialized; linking requires My device", `details: null` | `IDENTITY_EXISTS` "This client already has an identity (<name> <email>); it can't be changed. To use a different identity, start a separate client directory." plus `details.identity = { name, email }` |

The only change to an error code is NOT_FOUND for a nonexistent agent ID. I grepped `test/` and the contract docs (README, `docs/PARDNER-ACCEPTANCE.md`) for the old codes and messages. No test or documented contract asserted FORBIDDEN for that case, so the code change went ahead. Authorization order is the same as before: no revocation now succeeds where it used to be refused. The only difference is that a missing ID is reported before the ownership check.
