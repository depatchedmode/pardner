# F-004-02: Signed-out copy, invitation follow-up, Git note and People focus

Quick-fix unit qf-6. Findings: F-004-02, F-004-03, F-004-05, F-012-03, F-015-03, F-036-02, F-015-04, F-039-02, F-036-04, F-039-01, F-038-01, F-013-01, F-049-01, F-049-02.

## What was wrong

- The signed-out screen assumed an agent and named `pardner client open`. Other screens say `pardner open`. A reused link and an expired link showed the same notice, and the notice never said that links last 60 seconds (F-004-02, F-004-03, F-004-05, F-012-03).
- After Create invitation, the same invitation appeared twice: in the New invitation block and again in history, each with its own Revoke (F-015-03, F-036-02).
- "The invitation stays hidden…" stayed on screen after Show invite text (F-015-04).
- A revoked invitation still showed "Expires in 24 h" (F-039-02).
- Every Revoke button had the same accessible name (F-036-04).
- After a revoke, nothing on screen created a new invitation (F-039-01).
- In WebKit, clicking the read-only invite text did not select it (F-038-01).
- When Git supplied only a name, the identity step still said "Filled in from your Git configuration." (F-013-01).
- Closing a profile opened from the People dialog dropped focus to `<body>`, and getting back to the list took the "+N" button again (F-049-01, F-049-02).

## What changed (`ui-prototype/src/ClientApp.jsx`)

- SignedOut now reads: "Run `pardner open` on this computer, or ask your agent to. It signs this browser in without showing you a key." The failure notice reads: "This sign-in link was already used or is more than 60 seconds old. Links work once."
- InviteDialog:
  - History leaves out the invitation shown in the New invitation block. If that leaves history empty, it says "No other invitations."
  - The "stays hidden" sentence appears only while the text is hidden.
  - The expiry appears only while the invitation's state is issued.
  - The block's Revoke is labelled "Revoke this invitation". History Revoke buttons include the expiry, for example "Revoke Human invitation, Expires in 24 h · Nov 10, 11:02 AM".
  - "This invitation can no longer be used" now comes with a **Create another invitation** button. It mints a fresh operation ID, clears the block and creates a new invitation. A retry after a failure reuses that ID through the normal Create invitation button.
  - The invite textarea also selects its text on click.
- IdentityStep picks the Git note from the fields Git returned: both, name only ("Name filled in from your Git configuration; enter your email."), email only, or neither.
- A profile opened from the People dialog keeps the People dialog's opener (the "+N" button) as its return-focus target. Closing that profile reopens the People dialog. Closing the People dialog returns focus to "+N".

## Not addressed

- F-004-02's extra "Using a different browser?" hint about `pardner open --output-file FILE`. The triage spec kept to the main sentence.
- F-012-03: the restart wording is not centralised. `JOIN_HINTS.CLIENT_UNREACHABLE` still says "Ask your agent to reopen it". The disconnected banner and `CLIENT_NOT_RUNNING` live in other files.
- F-038-01's suggestion to size the textarea to its content: it stays at 5 rows.
- When the People dialog reopens, focus goes to its first control, not to the name of the person whose profile was just closed. Doing that would need a change in `Avatar.jsx`'s PeopleDialog.
- After Create another invitation, focus is not moved to the new Copy invite button.

## Verification

New test in `test/client-onboarding-ui.test.js` ("explains sign-in, the Git prefill, invitation follow-up and People focus in chromium"). It runs against the real local client service and checks:
- the signed-out copy and the reused-link notice;
- the name-only Git note, with global and system Git config hidden from the service;
- that history leaves out the shown invitation, and the hidden note is gone once revealed;
- that Revoke this invitation removes the expiry, and Create another invitation creates a second, issued invitation while the first stays revoked;
- People → profile → Escape reopens People, and Close returns focus to the "+N" button.

`npm run test:ui`: 66/66 pass.
