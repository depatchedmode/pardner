# F-079-01: issue link events read as raw operation types

**Unit:** qf-3 · **Findings:** F-079-01, F-080-01, F-128-02 · **Stories:** STORY-079, STORY-080, STORY-128 · **Severity:** medium

## Problem
History and Activity described GitHub issue link and unlink events with the fallback sentence, for example "Maya Okafor recorded task.link-issue on this task". The row showed the internal operation type and did not say which issue was involved.

## Change
`ui-prototype/src/events.js`: `describeEvent` now has cases for `task.link-issue` and `task.unlink-issue`. They name the issue as `repository#number`, taken from the event result, or from the payload when there is no result:

- "Maya Okafor linked issue acme/lantern-checkout#418 to Fix login"
- "Theo Lindqvist unlinked issue acme/lantern-checkout#481 from Fix login"

Inside a task panel the task reads "this task", the same as other History rows.

## Not changed
The triage note also suggested putting these events in the `commits` Activity filter group. They stay in `other`. The group is named for commits and branches, and moving issue links into it is a product decision, not a copy fix.

## Tests
- `test/event-copy.test.js`: link and unlink sentences, from the result and from the payload, and no "recorded" fallback.
- `test/pardner-ui.test.js` ("describes Activity and task History as plain sentences"): a seeded `task.link-issue` appears in History as "Carol Moreno linked issue acme/lantern-checkout#418 to this task", and the raw type does not appear.
