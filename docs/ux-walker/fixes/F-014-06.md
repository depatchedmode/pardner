# F-014-06: Profile labels, agent identity rows, initials and People header

Quick-fix unit qf-7. Findings: F-014-06, F-020-03, F-049-04, F-125-05, F-045-04, F-049-05.

## What was wrong

- Profiles labelled hand-typed values "Git name" and "Git email" (F-014-06).
- Agent profiles listed their human's Git name and email under the agent's Identity, so the agent looked as if it held that person's identity (F-020-03, F-049-04).
- "Cursor (ci)" got the initials "C(" (F-125-05).
- The People dialog put Close right after the title, while the other dialogs right-align it (F-045-04, F-049-05).

## What changed (`ui-prototype/src/Avatar.jsx`)

- `initials()` strips characters that are not letters or digits from each word before taking initials, so "Cursor (ci)" gives "CC".
- ProfileDialog labels the rows "Name" and "Email" and shows them only for humans. An agent profile shows Works for, Harness and Devices. "Works for" already names the human, and no new data is shown. The note under these rows now reads "Name and email are profile information. They do not sign anyone in." It is also shown only for humans, since agents no longer have those rows.
- PeopleDialog wraps its heading in a `<div>`, as ProfileDialog does, so `.profile-heading` right-aligns Close.

## Not addressed

- F-020-03, harness "Codex" shown when none was specified: this stays with the setup-agent issue, as triage decided.
- F-049-05, name buttons styled as underlined links: unchanged.
- Agent profiles still list devices. The device is where the agent runs, not part of the human's Git identity.

## Verification

New test in `test/client-onboarding-ui.test.js` ("shows letter initials and keeps an owner’s Git details off agent profiles in chromium"):
- the "Cursor (ci)" avatar renders "CC";
- the agent profile shows Works for, has no Name, Email, Git name or Git email rows, and does not show the owner's email;
- a human profile shows Email with the address.

A screenshot of the People dialog shows Close right-aligned. `npm run test:ui`: 66/66 pass.
