# Decision V4 — Focus moves into panels and comes back
Judged by one independent judge agent applying the usability, visual-craft and engineering lenses (scores are its reading). External judges (MUSE Wonder, Gemini Argon) were skipped: no OPENROUTER_API_KEY. Implementation order on one branch: V5 → V1 → V2 → V3 → V4.

| Proposal | Usability | Visual | Engineering | Total |
|---|---|---|---|---|
| A Targeted refs/effects | 4 | 4 | 5 | **13** |
| B focus.js hooks + inert | 5 | 4 | 3 | 12 |
| C Native <dialog> APG | 4 | 4 | 1 | 9 |

## Decision: A, with one graft for consistency with V3
- **Opener ref:** in Workspace, track the opener: a card (add `data-task-id` to `.task-card`), the **New task** button, or an Activity button. After `task.create`, the opener is the new task's card.
- **Restore on close:** Close and Escape both go through `setSelected(null)`. Restore focus in an effect after the panel unmounts. Fallback chain: opener (if connected and enabled) → **New task** (if enabled) → the pressed nav button.
- **Panel heading:**
  - `h2 tabIndex={-1}`, focused once per open when context loads.
  - The once flag is a Workspace ref keyed by the open. TaskDetail remounts on Actor switch (key `selected:actor`), and that remount must not steal focus from the Actor select.
- **Edit flow:**
  - Title `autoFocus` in edit mode as well.
  - After a successful Save or Cancel edit, focus **Edit task** once it re-enables (rAF).
- **Graft (V3 consistency):** when a submit fails, return focus to that form's submit button once it re-enables. The message is announced through `role=alert`, not focused.
- **Selected card:** `aria-current="true"` on the open card, plus `.task-card[aria-current]{border-color:var(--accent)}`.
- **PhoneAccess:** store the invoking button and refocus it after `busy` clears (rAF, only while the dialog is open). Otherwise focus Close.
- **Connection screen:** autoFocus the token field when `config.canManageAccess`, otherwise the pairing code.
- **Do not:**
  - convert the panels to `<dialog>`;
  - add `inert` (follow-up);
  - add Escape-to-close on New task (#120, gated on #121).

## Defense
- **vs B:** inert closes the gap where Tab reaches controls hidden behind the panel, but that gap is outside the criteria. B adds about 120 lines and risk in the tests.
- **vs C:** it breaks V1's scroll roots, and native Escape could drop drafts (#121).
- **Norms satisfied:** I7, A2, I6, I2.
- **Cost:** about 70 lines.

## Acceptance criteria
1. Opening a card focuses the details `h2`. Opening New task focuses Title.
2. Close or Escape on details, and Close on New task, return focus to the opener (matched by `data-task-id`) or to the fallback.
3. **Edit task** focuses Title. Save changes and Cancel edit return focus to **Edit task**. A failed Save focuses **Save changes**.
4. The open card has `aria-current="true"` and a distinct border.
5. After Enable, Save network and Generate new code, focus is inside the dialog, not on `body`.
6. With loopback admin, focus lands on Local service token on arrival.
7. Switching Actor with details open leaves focus on the Actor select.

## Test plan
- Card → heading focused. Escape → `activeElement.dataset.taskId === id`.
- Edit → Title. Cancel → Edit task. STALE_UPDATE → Save changes focused.
- Switching Actor keeps focus on the Actor select.
- Phone: after Generate new code, focus is inside the `dialog`.
- Fresh context: the token field is focused.
