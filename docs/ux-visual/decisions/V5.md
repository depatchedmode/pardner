# Decision V5 — User-authored Markdown gets its own subordinate scale
Judged by one independent judge agent applying the usability, visual-craft and engineering lenses (scores are its reading). External judges (MUSE Wonder, Gemini Argon) were skipped: no OPENROUTER_API_KEY. Implementation order on one branch: V5 → V1 → V2 → V3 → V4.

| Proposal | Usability | Visual | Engineering | Total |
|---|---|---|---|---|
| A Scoped .markdown | 4 | 4 | 5 | **13** |
| B Type tokens + prose scale | 4 | 4 | 3 | 11 |
| C markdown-body convention | 4 | 4 | 3 | 11 |

## Decision: A, with a token graft from B
- **Tokens** on `:root`: `--text-prose:15px; --text-prose-h1:16px; --text-prose-h2:15px; --text-prose-h3:14px`. These seed the deferred V6 type scale; chrome sizes are not touched.
- **Headings:** `.markdown :is(h1,h2,h3,h4){margin:1em 0 .4em;line-height:1.35}`.
  - h1 16/700, h2 15/700.
  - h3 14/600 muted, h4 14/600 muted.
- **Blockquote:** 3px `--line` left rule, `--muted` colour, 12px left padding.
- **Task lists:** `ul.contains-task-list{list-style:none;padding-left:1.6em}` gives a hanging indent.
  - `.markdown input[type=checkbox]{width:auto;min-height:0;padding:0;margin:0 .5em 0 -1.6em;vertical-align:-2px}` overrides the global `input{width:100%;padding:10px}` and the ≤760px 44px min-height, which are the root cause of #124.
- **Tables:** a react-markdown `components.table` override wraps each table in `<div className="md-table">` with `overflow-x:auto`.
  - No `display:block` on `<table>`, because WebKit then drops table semantics.
  - Cells: 1px `--line` borders, 6×10px padding, `border-collapse:collapse`, tinted `th`.
- **Code blocks:** `pre` gets scroll shadows via `background-attachment: local, scroll`, so the shadow appears only on overflow.
- **One renderer:** a single `MarkdownBody` component is used for both the description and comments.
- **Do not:**
  - use `li{display:flex}` (it breaks inline formatting);
  - style @mentions;
  - change chrome sizes.

## Defense
- **vs B:** restyling the chrome is the deferred V6 redesign. It would enlarge the diff without serving any acceptance criterion. Its token idea is kept as a seed.
- **vs C:** the designer's text was truncated, so it couldn't be checked; its idea is the same as A's.
- **Norms satisfied:** H3 (a stepped scale below the 20/17 chrome), H5 (description and comments match), I8/L6 (tables and code scroll inside themselves).
- **Cost:** about 50 CSS lines and 10 JSX lines.

## Acceptance criteria
1. In `.markdown`, h1, h2 and h3 are all smaller than 17px, with h1 ≥ h2 ≥ h3; h1 and h2 are bold.
2. Blockquote left border ≥ 2px; text colour = `--muted`.
3. Each task-list checkbox sits on the first line of its `<li>`, left of the text, ≤ 16px wide, inside the `<li>` padding box at 375 and 1440.
4. Table cells have a 1px border and ≥ 6×10px padding. A wide table scrolls inside `.md-table`.
5. An overflowing `pre` shows a scroll affordance; a short one shows none.
6. Styles are identical in descriptions and comments.
7. #124 can be closed.

## Test plan
A Playwright fixture (description + same comment) with h1/h2/h3, a quote, a task list, a table and a 200-char code line. Assert computed sizes; quote border; checkbox rect vs text Range (top within ±4px, `checkbox.right <= text.left`) at 1440 and 375; td padding; a 12-column table scrolls; `pre` backgroundImage; description and comment styles are equal.
