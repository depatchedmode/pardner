# Decision V3 — Errors appear where the work is
Judged by one independent judge agent applying the usability, visual-craft and engineering lenses (scores are its reading). External judges (MUSE Wonder, Gemini Argon) were skipped: no OPENROUTER_API_KEY. Implementation order on one branch: V5 → V1 → V2 → V3 → V4.

| Proposal | Usability | Visual | Engineering | Total |
|---|---|---|---|---|
| A Route ErrorNotice + split CSS | 4 | 4 | 5 | **13** |
| B Message component + hook | 4 | 4 | 3 | 11 |
| C Primer/Atlassian three-way split | 4 | 4 | 2 | 10 |

## Decision: A, with grafts from B and C
### Routing
- `submit` records `errorOrigin = {type, taskId}` from the operation type. This covers pre-operation validation errors and replays (`pending.type`).
- The single `ErrorNotice` renders in exactly one slot:
  - **New task:** above `.actions`.
  - **Task details:**
    - `task.update`: above the edit form's actions;
    - `task.handoff`: above **Hand off**;
    - `comment.add`: above **Add comment**;
    - everything else (`task.resolve`, `read.mark`, …): in a panel-top slot.
  - **No panel open:** the page slot.

### Page slot (graft from B)
- In normal flow in the chrome, directly under the header next to the pending notice.
- Delete the fixed `.app>.error` rules. Cap the slot with `max-height:30vh;overflow:auto`.

### Durability (graft from C)
- Dismiss appears only when there is no pending request. While `pending`, the routed message cannot be dismissed and keeps **Retry saved request** (`pending && !busy`) in whichever slot it sits.
- Close, Escape and Cancel edit clear `error` but never `pending`. The page-level `pending && !error` notice with Retry then takes over.
- New task stays disabled while a request is pending.

### Field errors
- `.field-error`: 13px `--danger-text`, 4px below the input. It keeps `role="alert"`, its `id` and `aria-describedby`.
- `input[aria-invalid=true]{border-color:var(--danger-line)}`.

### Tokens
- Add `--danger-text`, `--danger-bg`, `--danger-line`, `--warning-bg`, `--warning-line`, `--info-bg`, `--info-line`.
- `.notice` no longer shares the `.error` rule. Pairing-dialog notices use the warning tone.

### Connection screen
- `connectionError` carries its source (`pair` / `token` / `open`) and renders inside that form, or under the opening status.
- It scrolls into view (`scrollIntoView({block:'nearest'})`) and is cleared when the user edits the input.
- A generation ref drops load failures that resolve after Forget (P1-05).

### Do not
- Add toasts.
- Move focus to the message (V4 owns focus).
- Change error copy (#125).

## Defense
- **vs B:** the same placement, but replacing ~12 render sites risks breaking the Retry wiring. The valuable part, the in-flow page slot, is grafted in.
- **vs C:** focusing the message fights V4, and it is the largest migration.
- **Norms satisfied:** L7, L2, H4/H5, C3, I3.
- **Local-first:** Retry is never hidden behind a dismissed message.

## Constraints from tests
- Exactly one `role=alert` at a time (strict `getByRole('alert')` in `test/pardner-connection-ui.test.js:38,183`).
- Alert strings are unchanged.
- Retry appears only while `pending && !busy`.

## Acceptance criteria
1. A panel error renders inside that panel, above Save/Cancel/Add comment and never overlapping them, at 375 and at 1440.
2. The blank-title error's top is ≤ 8px below the input, it adds at most one line, and the input has `aria-invalid=true`.
3. `.error`, `.notice` and `.notice.warning` have distinct borders, and `.notice` is not red.
4. Without a pending request, Dismiss clears the error, and so do Cancel edit and Close. With a pending request, Retry is reachable within one action and replays exactly once.
5. A connection error renders inside the failed form, in the viewport.

## Test plan
- **STALE_UPDATE:** the alert box sits above Save. After Cancel edit, no alert remains.
- **Lost-response comment:**
  - Retry is inside the Task details panel.
  - Escape, then Retry from the page: it replays once and creates exactly one comment.
  - At 375 there is no Dismiss while the request is pending.
- **AMBIGUOUS_ACTOR:** Dismiss clears the alert and the draft is kept.
- **Blank title:** the error is at most 8px below the input.
- **Wrong token:** the alert is inside the token form, in the viewport.
