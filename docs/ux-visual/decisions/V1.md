# Decision V1 — The app frame stops scrolling; regions scroll
Judged by one independent judge agent applying the usability, visual-craft and engineering lenses (scores are its reading). External judges (MUSE Wonder, Gemini Argon) were skipped: no OPENROUTER_API_KEY. Implementation order on one branch: V5 → V1 → V2 → V3 → V4.

| Proposal | Usability | Visual | Engineering | Total |
|---|---|---|---|---|
| A Viewport flex column | 4 | 4 | 5 | **13** |
| B Named-region grid shell | 4 | 4 | 3 | 11 |
| C Trello/Linear frame | 3 | 4 | 2 | 9 |

## Decision: A, plus one graft from C
**Desktop frame.** Under `@media (min-width:761px) and (min-height:600px)`:
- `.app{height:var(--app-height);display:flex;flex-direction:column}`, where `--app-height` is `100vh`, upgraded to `100dvh` via `@supports`.
- `.app>*{flex-shrink:0}`.
- `.app>main{flex:1 1 0;min-height:0;overflow-y:auto}`.

**Board.**
- `.app>main:has(>.board){overflow:hidden;display:flex;flex-direction:column}`. `main` must itself be a flex container for the board's `flex` to work.
- `.board{flex:1 1 0;min-height:0;grid-template-rows:minmax(0,1fr);overflow:auto hidden}`.
- `.column{overflow-y:auto;overscroll-behavior:contain;scrollbar-gutter:stable}`. The gutter is the graft from C.
- `.column h2` is sticky, with the column background.
- Delete `.board{min-height:65vh}`.

**≤760px.**
- `html:has(.side-panel), html:has(.side-panel) body{overflow:hidden}`. `body` is included for WebKit.
- `.side-panel{overscroll-behavior:contain}`.

**JSX.** `<main key={view}>`, so a view switch never carries a stale scroll position.

**Do not.** No wheel-to-horizontal mapping, no per-view scroll memory, no chrome wrapper DOM.

**Interaction with V3.** V3 must remove the fixed `.app>.error` bar, which would otherwise overlay the columns.

## Defense
- **vs B:** same outcome, but it adds wrapper DOM, carries `display:contents` a11y risk, and changes the DOM paths V2–V4 rely on.
- **vs C:** wheel mapping steals vertical trackpad scroll, and scroll memory adds state nobody needs.
- **Norms satisfied:** L1, L2, L3, L7.
- **Cost:** about 25 CSS lines. Full-page screenshots now equal the viewport. Phones keep document scroll.

## Acceptance criteria
1. At 1024×700, 1440×900 and 1920×1080, the document height stays within the viewport (`scrollHeight <= innerHeight+1`) on:
   - Tasks with 40 cards in one column;
   - Goals;
   - Activity with 300 events;
   - any of these with the pending notice shown.
2. After scrolling `main` or a column, the header, **New task** and the nav are still visible (top ≥ 0).
3. Long columns scroll vertically; the board scrolls horizontally when narrower than its columns.
4. At 375 with Task details open, `window.scrollY` stays 0 on wheel.
5. With seed data, the header, nav and first card stay within ±2px of their current positions at 1440, 1920 and 375.

## Test plan
- **Desktop (`pardner-ui.test.js`):** seed 40 tasks via CLI. In each view, assert the document height inequality. Set a column's `scrollTop` to 1e6 and assert New task `y >= 0`. Switch views and assert `main.scrollTop === 0`.
- **Phone (`pardner-phone.test.js`):** open a task, scroll the wheel, and assert `window.scrollY === 0`. Run in Chromium and WebKit.
